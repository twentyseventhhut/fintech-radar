How it works
Android TVs have the same debug bridge as Android phones. Switch on USB debugging in the TV's
developer options, allow your computer once, and the rest is standard Android tooling:
 Back up the list of installed packages and settings.
 Disable the manufacturer's telemetry, ad services, content rows and preloaded junk with
 pm disable-user . Nothing is uninstalled, so a restore script can undo every step.
 Install a small native launcher and make it the default home screen.
The bloat differs by brand, so the prompt has your coding assistant discover it on your TV and ask
before touching anything you might use.
Quick start
You need a computer on the same Wi-Fi as the TV and a coding assistant with shell access.
Suggested: Claude Code on 0G Private Computer , one API key for 100+ models.
Claude Code with an Anthropic plan, Codex or Gemini CLI work too.
The assistant backs up, debloats, builds and installs the launcher, and checks each step with
screenshots pulled from the TV. With this repo as context it takes about fifteen minutes.
What you get
 A pitch-black home with a dock of your four favourite apps in a rounded band, where Apple TV puts it.
 A top shelf naming the focused app in large type, with an ambient glow in a colour taken from its artwork.
 The rest of your apps in a grid that slides up when you press Down.
 One floating glass highlight that springs from tile to tile. The focused tile lifts and shows its name.
 Three frosted buttons : Inputs (HDMI ports under the names you gave them in the TV's settings, AV, Live TV), Wi-Fi or Ethernet with the network name, Settings.
 A greeting, a thin clock and the date in Outfit , and a matching Clock screensaver. Set show_stats in config or a theme for one line under the clock: CPU, free memory and free storage. It stays off unless you turn it on, and it refreshes only while Home is on screen.
 Themes that change colours, wallpaper, dock and columns without a rebuild, and module cards that let other apps plug a tile in, only with your say-so.
And a TV that stops working against you: no sponsored rows, no "Discover" nags, no analytics
phoning home, no apps you never asked for.

Doing it by hand
Everything the assistant does, you can run yourself. The tools need Python 3 and nothing else.
Debloat list paths passed to disable.sh and restore.sh are relative to the directory you run
from, so your own lists can live outside the repository. Absolute paths also work.
Every script has a PowerShell twin next to it. On Windows with Android Studio installed nothing
else is needed:
The install scripts ask the TV which launcher owns Home and only disable one they recognise
( tvlauncher or launcherx ); pass STOCK_LAUNCHER=<package> ( -StockLauncher ) to override, or
 none to leave it alone.
 tools/disable.sh ( disable.ps1 ) applies the same rule before it disables anything: if the list
contains the app that owns Home and no other app on the TV answers HOME, it skips that entry, says
why, and disables the rest of the list. So a list applied before the launcher handover cannot leave
the TV with nothing to start. Run the same list again once launcher/build-and-install.sh has made
the new launcher Home and the entry is applied; FORCE_HOME=1 ( $env:FORCE_HOME ) disables it anyway.
The launcher
A small native Android TV app ( com.gathin.tvhome , about 390 KB installed) in plain Java with
AndroidX RecyclerView and nothing heavier. Built for sets with 1 GB of RAM: no blur, no video, no
network, no background services. It needs JDK 17 and Android SDK platform 34 to build; on macOS,
 brew install openjdk@17 android-commandlinetools and sdkmanager "platforms;android-34" "build-tools;34.0.0" . On Linux
the install script finds ~/Android/Sdk and the java on your PATH.
 Configure in config.xml : dock order, hidden apps, the Live TV package, columns (tiles shrink from 5 up), rows under the dock, an optional VPN app for the network pill, and reduced_motion for TVs whose GPU cannot keep up.
 App library (optional): enable app_library in config.xml or a theme to browse installed apps and add or remove Home shortcuts with the remote. See the app library guide .
 On-TV launcher settings: click Settings for the TV's system settings, or hold OK on Settings and choose Launcher settings to set 4, 5, 6 or 7 apps per row, turn animations on or off, and opt into advanced effects. The advanced option adds tile lift, icon zoom and smooth ambient-colour transitions; it may use more memory. Use Follow theme to clear on-TV choices. Pushing or resetting a theme also clears them.
 Change the default home: Launcher settings and the optional Default-home tile ( show_home_settings_shortcut ) open Android's home picker. Choose the original launcher to stop using CleanYourTV as Home, or CleanYourTV to return. The original launcher must be enabled. If the install script disabled it, use the restore script below first. Some TVs provide no home picker.
 Themes set the same keys plus a background colour and a wallpaper from a config.json pushed to the TV, no rebuild. Four ship in themes/ , documented there.
 Language follows the TV: English, German, Spanish, Catalan, French, Russian, Serbian (Latin), Polish, Portuguese, Turkish, Arabic, Hebrew, Simplified Chinese, Traditional Chinese (Taiwan), Thai, Finnish, Vietnamese, Bangla. The launcher asks you once per app, Keep hidden by default, and remembers the answer for that app's signing key and card name. Hold OK on Settings and choose Module cards to change your mind. How to make one: docs/modules.md ; the contract: docs/specs/card.md .

 Remote keys : an optional accessibility service keeps the remote's Input button working on Google TV ( INPUT_KEY_SERVICE=1 at install) and can bring back other buttons only the stock launcher answered, such as the YouTube button ( app_keys and input_key_keycodes , in config.xml or a theme; HOME_KEY_SERVICE=1 reads app_keys too), another fixes sticks whose Home key sends ALL_APPS and opens Settings from the remote's gear button, even one Android does not map ( HOME_KEY_SERVICE=1 , scancodes or keycodes in config.xml ). With settings_key_panel the gear opens a small quick settings panel instead, over Home or any app: TV settings, Display, Network, Apps and Launcher settings.
 Navigation is deliberate: Up and Down move one row, the top buttons never fall through to tiles and Down from them returns to the dock tile you came from, the last focused app is remembered, and installing or removing an app refreshes the tiles while Home is open.
 Artwork : app banners load at xhdpi or better, so low-density TV UIs do not downsample them before the focus zoom.
Restoring your TV
Before tools/disable.sh changes anything it writes down what the TV looked like: for every package
in the list whether it was enabled, already disabled or not installed, which component owned Home,
and the three animation scales. That record lives in ~/.cleanyourtv/ , one file per TV and list, and
a second run of the same list keeps the first record instead of saving the cleaned-up state over it.
If you added packages to the list since, that run adds them to the record before disabling them.
Keep the list you applied. The restore script replays the record, so a package you had disabled
yourself stays disabled and Home goes back to the component that owned it:
The stock launcher argument is only a fallback: with a record, the launcher that actually owned Home
is the one that gets it back, and the argument is used only when nothing answered HOME at the time
or this project's launcher owned it. The stock launcher is enabled again either way, unless it was
already disabled when the record was taken.
Without a record (an older run, or a record you deleted) the script says so and falls back to
enabling the whole list and resetting the scales to 1.0 , which is what it used to do.
It leaves the new launcher installed (remove it from the TV's Settings → Apps if you want it gone)
and does not know about packages you disabled outside the list. To switch back later, run the
install script again; it works out which launcher to disable even when Home has fallen back to
Android's chooser. If the TV is unreachable, its own
Settings → Apps page can re-enable packages too.
When something goes wrong
The full list of things that bit us is in docs/TROUBLESHOOTING.md . The
three that matter most:
 macOS blocks adb connect ("No route to host") under Local Network privacy. tools/tv.py avoids the binary.
 Disable the stock launcher only after the new one is installed and running , or Home lands on a factory test app. The install script orders this for you.
 On Google TV the setup wizard ( com.google.android.tungsten.setupwraith ) can take Home and crash-loop the system after the stock launcher is disabled. Disable it too, and list it in your debloat.txt so restore brings it back. But check dumpsys wifi | grep -o 'cname=[^ ]*' first: if the Wi-Fi network was saved during setup it belongs to setupwraith, and disabling it deletes the network (re-join it in Settings first; tools/disable.sh skips setupwraith until you do). Stuck already? tools/tv.py 'pm enable --user 0 com.google.android.apps.tv.launcherx' .
Questions people ask
 Is this safe? Can it brick the TV? Nothing is flashed, rooted or deleted; packages are disabled
in the user profile. The risk is disabling something the TV leans on, which is why lists are
applied in small batches with a restore script ready. The TV's own Settings → Apps page can
re-enable packages even without the tools.
 What about firmware updates? Most lists disable the update service, so updates arrive only when
you re-enable it. If one lands, the worst case is a package coming back and you re-run the script.
 Won't the apps break? Streaming apps still update through the Play Store, which is left alone.
The launcher just lists what is installed and launches it with intents that have been stable for a decade.
 Can I do this for someone in another home? Yes, over a private Tailscale 
link instead of the same Wi-Fi: either Tailscale on their TV, shared with you, or a computer or Apple
TV at their home routing to it. Never by opening the ADB port on their router. Step by step in
 docs/REMOTE.md .
 Isn't ADB access a security hole? It is one explicit "allow this computer" tap on the TV, the
same as developing an Android app. Network ADB is plaintext on port 5555, and on firmware with
 ro.adb.secure=0 any device on the LAN gets a shell, so close it when you are done:
On the TV: Developer options → turn USB debugging and Network/ADB debugging off, and
revoke the USB debugging authorisations.
Reboot the TV, then confirm the port is gone from your computer: nc -vz <tv ip> 5555 must fail.
Without nc (Windows): python tools/adb-closed.py <tv ip> must say the port is closed.
The launcher keeps working without debugging.
 Can it block ads inside apps too? Partly, with Android's Private DNS (Android 9 and newer). Point
it at an ad-blocking resolver such as AdGuard DNS and every app's ad and

The prompt
Paste this into Claude Code (or another coding assistant with shell access) on a computer that is
on the same Wi-Fi as the TV. Works on Android TV / Google TV sets (Xiaomi, TCL, Hisense, Sony,
OnePlus, Realme, Nvidia Shield and most others). It will not work on Samsung Tizen, LG webOS or
Fire TV. If you cloned this repo, mention that: the assistant can reuse tools/ and launcher/ 
instead of writing them from scratch, and only needs to edit launcher/.../values/config.xml .
Before you start, on the TV: Settings → Device Preferences → About → press OK on "Build" 7 times,
then go back → Developer options → turn on USB debugging (and Network/ADB debugging if your TV
shows it). Keep the TV on. Some boxes cut power to their USB port while USB debugging is on, so a
USB speaker or drive plugged into it goes dead until you switch debugging off again.
I want to debloat my Android TV and replace its launcher with a clean Apple TV style home screen.
My TV model is: . Work on the real device, step by step, and verify everything you
do with screenshots pulled from the TV. Ask me before anything that depends on my preferences.
Connect
Find the TV on my network (hostname, ARP table, or ask me for the IP) and connect over ADB on port 5555.
If the TV is in another home, I'll give you its Tailscale address instead (docs/REMOTE.md): use that,
don't scan my local network.
If the stock adb binary fails with "No route to host" on macOS even though the port is open, that is
macOS Local Network privacy blocking adb. Don't debug it: use the Python adb-shell package in a venv
as the ADB client instead. If its file push hangs on larger files, transfer files as base64 chunks
through the shell and verify the md5.
If port 5555 stays closed, the TV may only offer Wireless debugging (Google TV sets often do): look for
 _adb-tls-connect._tcp with dns-sd -B or adb mdns services , ask me for the code and port under
Developer options > Wireless debugging > Pair device with pairing code, then adb pair , adb connect 
and adb tcpip 5555 . Android switches Wireless debugging off whenever Wi-Fi drops.
Tell me when the "Allow USB debugging?" prompt will appear on the TV so I can accept it.
If adb install hangs on Android 14 it is waiting for an on-screen confirmation; push the APK and run
 pm install -r over the shell instead.
Back up first
Save the full package list, disabled-package list, getprop output and all settings to a backup folder
before changing anything, and write a restore script that re-enables everything you disable.
Ask me what is plugged into the TV's USB ports. Some devices cut their power while USB debugging
is on, so warn me, and remind me to switch debugging off once you're done.
When you finish, close network ADB instead of leaving it open: switch USB debugging and
Network/ADB debugging off on the TV, revoke the USB debugging authorisations, reboot, and check
that nc -vz <tv ip> 5555 fails. Port 5555 is plaintext, and on firmware with ro.adb.secure=0 
any device on the LAN can get a shell.
Debloat
List installed packages and sort them into: manufacturer telemetry/analytics, manufacturer content
and ad services (PatchWall, recommendation rows, content providers), background services I probably
don't need (share/cast duplicates, cleaners), preloaded apps, and streaming apps.
Disable the first categories with pm disable-user --user 0 , never uninstall system packages.
Never disable what the TV needs to work: the TV app and input services that play HDMI and the
tuner, the input/source menu, remote control and Bluetooth pairing services, the on-screen
keyboard, Google Play Store and Play Services. Manufacturer package names often don't say what a
package does: check its activities and services with dumpsys package first, and ask me if it's
still unclear.
Before touching streaming apps, voice assistant, Chromecast, Miracast or the update service, ask me
which ones I use with a checklist question and disable only what I don't tick.
Run pm commands one per shell call, chained commands may silently stop after the first.
Disable in small batches and screenshot between them: a batch can take something load-bearing with
it and you cannot tell which.
Offer me ad-blocking DNS as an optional extra: on Android 9 and newer, Private DNS set to an
ad-blocking resolver ( settings put global private_dns_specifier dns.adguard-dns.com , then
 settings put global private_dns_mode hostname ). Tell me it doesn't block YouTube ads, check an app
still plays afterwards, and note the undo ( private_dns_mode opportunistic ) in the README.
Launcher
Check that the TV accepts APKs before building anything. Some China-market sets answer every
sideload with INSTALL_FAILED_VERIFICATION_FAILURE — adb install , pm install , a hand-started
installer and even the manufacturer's own APKs all fail — and others refuse any package that
declares android.intent.category.HOME unless it carries the manufacturer's signature. If you
hit either, do the debloat half, say plainly that the launcher half is impossible here, and stop
retrying installs. The matching examples/ header says which case your TV is.
Don't install a third-party launcher that charges for basics like wallpapers. Build a small native
Android TV launcher instead (Java, AndroidX RecyclerView, minSdk matching the TV, debug build is fine),
install it over ADB, set it as the default home and disable the stock launcher. If several apps claim
the HOME intent, list them with cmd package query-activities -a android.intent.action.MAIN -c android.intent.category.HOME and set the default with cmd package set-home-activity .
Before disabling the stock launcher, check which other apps claim HOME: on Google TV the setup wizard
( com.google.android.tungsten.setupwraith ) takes over even after the stock launcher is disabled, and
the matching examples/ header says what to do. Before disabling setupwraith, run
 dumpsys wifi | grep -o 'cname=[^ ]*' : a Wi-Fi network saved during first setup belongs to it, and
Android deletes that network the moment it is disabled, which takes the TV off Wi-Fi and ADB. If it
does, ask me to forget the network and re-join it in Settings first.
On Google TV the stock launcher also answers the remote's app buttons (Netflix, YouTube and the like),
Input and Settings/dashboard buttons, so after disabling it ask me to press each one, and remap any that
do nothing with the launcher's key services: input_key_keycodes and app_keys with
INPUT_KEY_SERVICE=1, settings_key_keycodes with HOME_KEY_SERVICE=1 ( config.xml or the theme).
On Android 11 and newer the launcher must declare <queries> for android.intent.category.LEANBACK_LAUNCHER ,
or package visibility silently hides every app and the grid comes up empty; target a recent SDK, some
Google TV 14 sets refuse older targets at install.
Design, Apple TV 4K style: pitch black background; a dock row at the bottom of the screen inside a
slightly lighter rounded band holding the four apps I pick (ask me which, and the order); the rest of
the apps in a 4-column grid below that scrolls up when I press Down; one translucent "glass" highlight
that springs from tile to tile instead of per-tile borders; the focused tile scales up slightly and
shows its name underneath; above the dock, the focused dock app's name in large light type with an
ambient glow in a colour sampled from its banner; frosted pill buttons top right for Inputs, Wi-Fi
(showing the network name) and Settings; a greeting, a large thin clock and the date top left in a
downloaded open-licence typeface such as Outfit. Inputs opens a compact glass dropdown under the pill
listing the HDMI ports, AV and Live TV, switching via the TV input framework.
Make D-pad navigation deterministic: Up/Down move exactly one row, Up from the dock goes to the top
bar, the ends of the top bar don't fall through to tiles. Remember the last focused tile.
Keep it light: the TV has about 1 GB of RAM. No blur, no video, no network polling.
Verify
After each change, inject remote key presses over ADB, take a screenshot from the TV and look at it.
Fix what you see before moving on.
Live TV and HDMI screenshots come back empty (0 bytes); that is the TV, not a broken debloat. Check
 dumpsys activity activities | grep topResumedActivity instead (see docs/TROUBLESHOOTING.md ).
If a remote button relies on an accessibility helper, check that the service is enabled and bound
for the current user, then ask me to press the real button; an injected key is not proof (see
 docs/TROUBLESHOOTING.md ).
When done, give me a restore script, a build-and-install script, and a README that explains how to
re-enable any app and how to change the dock order or the wallpaper.
Expect to answer three or four checklist questions (which apps you use, which four go in the dock,
whether to keep the voice assistant, Chromecast and firmware updates). Everything is reversible.

A consumer-tech meme, not a fintech event. Works on Android TV/Google TV (Xiaomi, TCL, Sony, Hisense, OnePlus, NVIDIA Shield…); **Samsung Tizen, LG webOS and Roku are out** (different OS); Fire TV gets the debloat half only (Fire OS won't yield Home to a third-party launcher).

**Risk flags.** (1) **Platform countermove / disintermediation risk** — the tool depends on an open ADB interface and on OEMs not signature-locking HOME; the China-TCL `INSTALL_FAILED_VERIFICATION_FAILURE` cases and the Tizen/webOS/Fire TV exclusions show OEMs can and do close the door, so the "exit" is revocable. (2) **Security surface** — Network ADB on port 5555 is plaintext and on `ro.adb.secure=0` firmware any LAN device gets a shell; an agent-run debloat that forgets to close it leaves the TV exposed (the repo warns, but it is on the user). (3) **Revenue-model threat to the incumbents** — if debloating/ad-opt-out scales, it chips at the home-screen + ACR data monetisation Roku/LG/Samsung are explicitly leaning on, pressuring the very platform-revenue growth (Roku +18%) that offsets thin hardware margins; near-term immaterial given niche adoption, but directionally against the OEM ad thesis.

**What this changes (idea-lens).** `(analysis)` The signal is agentic automation turning a messy manual hack (ADB + custom launcher) into a ~15-min guided task — a template that generalises to other "de-enshittification" chores users will pay attention to, not money, for. Falsifiable thesis: this stays a hobbyist niche and does not dent CTV ad economics — it breaks if (a) a major OEM feels enough pressure to ship a native "clean home screen" toggle, or (b) OEMs retaliate by locking ADB/HOME, which would itself confirm the home screen's revenue value. Watch Roku/LG platform-ARPU trajectory and any OEM move on ADB access as the trigger.
